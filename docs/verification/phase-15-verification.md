# Phase 15 — EventBridge Event Routing & Fan-Out Verification

## 1. Status

**Status: COMPLETE**

## 2. EventBridge Architecture

- **Producer**: Domain services (Simulator, Weather poller, Sensor API) publish events via `EventBridgeEventPublisher`.
- **Publisher**: Serializes canonical events into AWS EventBridge `PutEvents` batches. Checks limits and returns per-item results.
- **Event Bus**: Custom bus `floodguard-dev-events` isolates our events.
- **Rules**: Explicit pattern-matching rules (e.g. `floodguard-v1-environment-events`) route events based on `detail-type` and `source`.
- **Targets**: Rule matches fan-out to SQS queues and Audit sinks. Target failures are independent.
- **SQS**: Standard queue receives wrapped messages.
- **Consumer**: Uses `EventBridgeSqsMessageAdapter` to unwrap the EventBridge envelope and feed the canonical `TransportEnvelope` to domain handlers.

## 3. Event Bus

- **Name**: `floodguard-dev-events` (Environment-named strategy: `floodguard-{env}-events`)

## 4. EventBridge Mapping

| Domain Field / App Config | EventBridge PutEvents Field |
| --- | --- |
| `eventbridge_source` config | `Source` (`com.floodguard`) |
| `event_type` | `DetailType` (e.g. `environment.weather_observed`) |
| Canonical JSON Envelope | `Detail` (The full Phase 14 `TransportEnvelope`) |
| `eventbridge_bus_name` config | `EventBusName` (`floodguard-dev-events`) |
| `occurred_at` | `Time` (Optional in PutEvents, EventBridge sets arrival time, but canonical `occurredAt` in `detail` remains authoritative) |

## 6. Fan-Out

**Test**: A weather observation event is published.
**Result**: 2 targets reached (SQS and Audit Sink).
The `eventId` and `correlationId` remain identical in both targets. The Audit target failure does not mutate or block SQS delivery.

## 7. Transport Modes

- `IN_PROCESS`: Uses `InMemoryEventPublisher` and `InMemoryEventBus`. Completely bypasses queues. Best for simple local dev.
- `SQS`: Uses `SqsEventPublisher`. Domain events go straight into the SQS queue.
- `EVENTBRIDGE`: Uses `EventBridgeEventPublisher`. Events go to EventBridge, rules route them to SQS (and other targets), consumer unwraps and processes.

## 8. Event Identity

- **eventId**: Preserved end-to-end within the canonical payload inside the EventBridge `Detail`.
- **correlationId**: Preserved.
- **causationId**: Preserved.
- **EventBridge ID**: Extractable from `id` on the outer envelope.
- **SQS message ID**: Distinct ID generated by SQS upon receipt.

## 9. Partial Failure

**Test**: A batch of 10 events is submitted. The EventBridge emulator simulates 8 successes and 2 failures.
**Result**: The publisher accurately reflects this: 8 events return success and an event ID, 2 events return failure and an `InternalFailure` error code. SQS and Audit Sink both receive exactly 8 events. `eventbridge_partial_failure_total` metric is incremented.

## 10. EventBridge → SQS Adapter

The `EventBridgeSqsMessageAdapter` examines incoming SQS message bodies. If it detects an EventBridge wrapper (presence of outer `source` and `detail`), it unwraps the payload, deserializes the canonical `TransportEnvelope` from the `detail` node, and associates the EventBridge ID for logging. If no wrapper is found, it parses the direct SQS message (maintaining backward compatibility).

## 11. Duplicate Result

**Test**: Duplicate EventBridge deliveries of the same event.
**Result**: 1 logical mutation. Redis idempotency (`PROCESSING`/`COMPLETED` atomic leases) successfully drops the duplicate, preventing redundant risk updates and rerouting.

## 12. Out-of-Order Result

**Test**: A newer weather event arrives, followed by an older one.
**Result**: The older event does not regress the state. The newer event's risk state remains authoritative.

## 13. EventBridge-to-Reroute Test

**Flow**:
1. Simulator publishes `SimulationEvent` to EventBridge.
2. EventBridge `simulation-events` rule routes it to SQS.
3. SQS consumer polls, adapter unwraps, handler processes.
4. `RuntimeRiskState` revision increases.
5. Internal event bus broadcasts `risk.edges_changed`.
6. Realtime reroute coordinator recalculates the route.
7. SSE emits replacement geometry to the browser.
**Result**: End-to-end traversal works perfectly in `< 5ms`.
